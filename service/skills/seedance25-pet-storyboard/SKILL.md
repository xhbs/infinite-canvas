# Seedance 2.5 萌宠分镜

以导演思维设计每个情节拍：先判断戏剧意图、观众此刻需要看到的信息和情绪节奏，再决定镜头。使用准确、可执行的专业拍摄术语描述景别、机位、角度、构图、镜头运动、焦点和剪辑切点；术语必须服务画面表达，不用泛泛的“电影感”代替具体设计。

把用户提供的剧本转成准确、可执行的 Seedance 2.5 视频提示词。参照 Seedance 2.5 官方提示词组织方法，按“生成目标、参考素材职责、主体与事件、视觉和镜头表达、声音、保持一致”等需要的模块编排；分镜正文按连续秒数区间描述。保留剧本和用户明确指定的情节、角色状态及约束；围绕短小、可见的动作设计生动表演与镜头，不擅自补全现实流程、强化因果或拖入承上启下的动作。Seedance 可补足未限定的普通细节，不把提示词写成对画面的过度规定。

## 工作流程

1. 每个新剧本开始时确认本片输出画幅。即使剧本写了画幅，也要确认是否沿用；确认前不开始资产审核、图片生成或视频段设计。单张资产图的构图比例按用途决定，不必等于视频画幅。
2. 阅读剧本，提取角色、场景、道具、视觉约束和可拍的情节单元。整片采用滚动设计：先处理开头一段；当前段确认后，再依据已确认内容和剩余剧本设计下一段。不要提前锁定全片总时长。
3. 先在画布 Agent 会话中提交资产需求表，使用 [references/asset-review-template.md](references/asset-review-template.md)。此时只列需求，不生成图片；资产申请只在会话中沟通，不创建文本节点或文档。以用户最新编辑为准；若无法辨认哪份表最新，或复用范围等关键信息不明，先在会话中询问。
4. 用户确认资产需求后，才使用当前画布实际提供的图片生成能力 `generate_image` 创建获批的参考图节点。纯文生图的 `sourceNodeIds` 传空数组；借鉴画布参考图时只传真实且相关的图片节点 ID。若当前画布工具不可用，说明缺少的能力并等待用户提供可用入口，不自行改用其他生图途径。生成提示词须落实本 Skill 的角色姿态规则及项目适用的 `AGENTS.md` 约束。
5. 图片生成后告知用户对应的画布节点并等待用户自行目视审核，不擅自视为已通过。用户拒绝某张图时，按反馈生成替代图并等待复核；保留原图及其他资产，除非用户明确要求删除。
6. 每个视频单元的镜头设计严格遵守 [references/shot-by-shot-design.md](references/shot-by-shot-design.md)，按镜头顺序逐镜澄清、设计并等待用户确认；不得预先完成整段所有镜头。用 [references/shot-review-template.md](references/shot-review-template.md) 累积已确认镜头，每镜完整覆盖模板要求的设计维度。逐镜确认阶段不附完整 Seedance 视频提示词。用户确认当前镜头后，才把它加入本单元审核表画布文本节点；后续修改此节点，不重复创建草案。
7. 本单元所有镜头逐一确认后，检查完整审核表中的时间连续性、动作方向、角色与道具站位、视觉基准、镜间连续性和切点。按 [references/shot-line-art.md](references/shot-line-art.md) 使用画布实际图片生成能力一次性生成整段多宫格线稿总览，作为独立画布图片节点交用户审核。线稿审核图不得列为视频提示词的参考素材，也不得上传或关联到视频节点。用户提出修改时按要求更新镜头设计；未明确要求时不自动重生成线稿。
8. 用户确认线稿总览可以继续后，才依据本单元全部已确认镜头设计撰写完整 Seedance 提示词，另存为画布文本节点，与审核表分开。每段交付时标明总时长、已确认画幅、实际引用素材及其职责、动作和声音限制。用户明确确认可以生成后，才使用 `generate_video` 创建视频节点或提交生成；按用户确认逐段继续。

## 角色姿态

姿态按场景、动作和身体力学决定，不默认所有镜头都采用拟人直立，也不默认所有镜头都采用四足姿态。生成提示词、镜头审核表和线稿总览中都要落实实际姿态；不能只在审核说明里提及。

- 空手普通走路或奔跑时，默认采用猫咪自然的四足姿态；场景明确需要拟人化表演时，可以采用双足行走或奔跑。
- 需要用前爪拿取、握持、搬运或操作物件时，角色以后肢支撑身体，由前爪完成动作。持物移动时保持双足姿态，直到放下物件。
- 挥手、指方向、打招呼等把前爪作为手来表演的拟人手势，采用以后肢支撑的直立姿态；普通猫咪行为按场景采用自然姿态。
- 等待、观察、休息、睡觉等没有持物、操作或拟人手势的场景，采用符合情境的猫咪自然姿态，例如四足站立、坐姿或趴卧。
- 场景线索明确时直接据此设计。若两种姿态都合理，且选择会影响动作表达或镜头连续性，先询问用户。用户主动指定的镜头姿态优先级最高；局部指定只适用于其明确范围。
- 局部脸部或道具特写不必为了表现全身姿态而改变取景，但动作设计仍须符合角色身体结构。

## 资产规则

- 只申请对角色、空间、反复出现或需要精确呈现的道具有一致性帮助的参考图；一次性、外观普通且文字足以说明的物件通常不申请。
- 默认将新生成资产作为当前画布的图片节点管理，不另行下载或保存到本机目录。只有用户明确要求本地文件或确认属于公共资产时，才按指定目录导出/保存；目录未知时先确认，不猜路径或覆盖同名文件。已有公共资产可按原路径导入或引用，无需复制。
- 不使用本地“本集目录/资产图”管理画布资产。用户确认某项资产可跨单元复用后，将外观设定、复用范围和参考图职责整理为画布文本节点；图片本身保留为图片节点。不要声称文本节点或图片节点会自动跨画布共享；只引用当前画布中可查到的真实节点。
- 每份参考图注明负责锁定的特征、使用的时间段/镜头，以及不应继承的背景、排版、光线或多余元素。仅在对应镜头调用，不让素材默认影响全片。
- 资产需求申请只在 Agent 会话中回复。用户确认后的公共资产说明、生图提示词草案、镜头审核表和分段视频提示词使用画布文本节点；一般草案用 `create_text_node`，更新已审核草案优先用 `update_text_node`。只有新创作流程首次创建正式主剧本或总制作稿时才用 `create_primary_script_node`。
- 创建图片或视频时只传真实存在且确为直接来源的 `sourceNodeIds`，不虚构节点 ID 或素材编号。提示词中的素材职责要能对应到这些真实图片节点。

## 分镜规范与模式

所有视频段都遵循 [references/storyboard-rules.md](references/storyboard-rules.md)：按时间区间呈现连续事件，每个区间内可包含一个或多个具体镜头；每镜明确景别、机位/角度、构图、镜头内运动或固定状态、动作表演、切点和声音。时间区间用于分配事件节奏，镜头切点需独立写明。机位固定、镜头跟拍和切镜频率是不同决策；少用跟拍不等于少切镜。

设计本段镜头和视觉基准前，读取以下两份参考，并用于审核表、正文和提交前检查：

- **相机四维编码：** [references/camera-codec.md](references/camera-codec.md)。用 Z 景别、Y 高度与俯仰、X 方位、F 光学/观看身份/构图检查镜头，另定固定或运动路径及节奏。编码是设计工具，最终提示词用自然语言表达；不强制默认焦段、浅景深或缓入缓出。
- **深度美学约束：** [references/aesthetic-constraints.md](references/aesthetic-constraints.md)。明确本段必要的光源与光行为、关键材质、配色和构图，并在对应镜头落实。延续已确认风格；Octane 等渲染观感、冷暖强对比、极简等为可选方案，不统一套用。

- **默认：按秒模式。** 读取 [references/mode-by-second.md](references/mode-by-second.md)。提示词正文按连续、不重叠的秒数区间组织；每段按事件节奏定长，不机械逐秒切片。
- **固定30秒模式。** 仅在用户明确要求时读取 [references/mode-fixed-30.md](references/mode-fixed-30.md)。沿用按秒和镜头规范，分配完整30秒时间线，并保留必要时跨段重叠接续的规则。

根据场景复杂度读取 [references/prompt-anatomy.md](references/prompt-anatomy.md) 的 Seedance 2.5 提示词模板与结构示例。时长、画幅等生成参数在生成界面/接口设置；如用户已有开头或结尾声明，保持其职责与措辞，中间事件正文按秒数区间组织。字幕/画面文字和声音标记规则见共同规范。

## 工具流程

- 只使用当前画布 Agent 实际提供的工具。提示词初稿、资产需求审核和修改都在 Agent 会话中完成；确认后的参考图使用 `generate_image` 创建图片节点，审核表、资产说明和视频提示词使用 `create_text_node` / `update_text_node` 保存。用户明确确认某段视频可以生成后，再确保实际使用的参考图已在画布中并调用 `generate_video`；未经确认不创建视频节点或提交生成。
- 线稿审核总览只在本单元所有镜头都逐一确认后生成；使用 [references/shot-line-art.md](references/shot-line-art.md) 执行，并作为独立画布图片节点供用户审核。线稿仅供审核，不进入视频生成素材或视频节点。
- 不假设当前 Agent 可调用 Codex 本地生图 skill、New API、`canvas-local-image` MCP 或 `infinite_canvas` MCP。若所需画布工具不可用，说明缺少的能力并等待用户提供可用入口。

## 修改原则

尊重用户在对话或 Markdown 中直接做出的修订。反馈落到具体动作、表演、机位、切点、状态或声音上；只修改用户要求及保证结果正确所必需的部分，不以“加强表现”代替具体设计。
